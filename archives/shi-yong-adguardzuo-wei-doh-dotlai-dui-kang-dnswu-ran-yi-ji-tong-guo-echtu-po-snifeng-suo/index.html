一些发现和踩坑

踩坑和发现就放到前面了, 目前部署的dot可以访问google/youtube/steam/github, doh可以额外访问e-hentai/exhentai/x/pixiv

dot和dns差不多只提供了解析域名的服务, 所以被sni阻断的域名只靠dot无论如何都无法访问

google以及youtube的所有域名居然全都没有被sni阻断, 完全没想到, steam是只阻断了社区steamcommunity.com之类的域名github是纯dns污染

这里有一个让我觉得非常傻逼脑残的点, 尼玛的steam安卓app是基于steamcommunity的webview

GFW似乎还有偶发性的sni阻断一下github和steam, 这点尚未证实我不做保证, 也可能是地区性的问题或者运营商的问题, 不太确定

只要是托管于Cloudflare并开启了Cloudflare CDN的网站都能通过ech加密来突破sni封锁, 即使网站没有开启ech, pixiv.net^$dnstype=A,dnsrewrite=NOERROR;A;104.18.10.118 直接将域名重写到Cloudflare的ip或者域名即可

3. 国内探针

由于海外 VPS 无法准确测量国内不同运营商至境外 CDN 的实际丢包和延迟，因此将测速与清洗工作部署在国内腾讯云 VPS上。

简要说明, 如果你的本地或vps配置了代理一定要让脚本跳过代理, 否则得到的ip可能是无法连通的
不要使用ICMP/TCP Ping, 这样得到的结果不一定可用, 一定要用真实HTTP/HTTPS连接有效
github是有部分ip被官方封锁的一定要注意

1. 深度优化原则与避坑

  1. 废弃虚假的 ICMP/TCP Ping，全面改用端到端 HTTPS 应用层探测：

    • Ping 测的 ICMP 单包仅 64 字节，即使跨洋丢包率达 30%，偶尔溜过一个包也会显示“通（300ms）”；

    • 真实网页需要完成 TCP 握手 + TLS 1.3 协商拉取 4KB+ 证书链 + 接收 HTTP 首包。在 300ms 高延迟线路上稍有丢包就会触发指数退避重传，直接引发浏览器超时；

    • 探针实现 test_https_latency，必须验证 TLS 证书合法有效且取得合法 HTTP 响应码才判定节点存活。

  2. 探针强制跳过本地/系统代理：

    • 探针机器若配置了梯子或系统代理（如 127.0.0.1:7890），会导致测出来的是代理速度而非国内直连网络；

    • 脚本开头强制清除所有代理环境变量，并注入 ProxyHandler({})，确保探测结果 100% 对应国内原生网络。

  3. 集成 Dogfight360 (UsbEAm / S302) 核心 CDN IP 池：

    • 提取近 1000 个细分 CDN 节点，利用 Fastly_C 专属网段（167.82.x.52）解决 Steam 预告片与静态卡死，利用 Fastly_D（167.82.x.133）加速 GitHub 文件下载，利用 352 个 Akamai 节点为 Steam 社区与头像加速。

  4. GitHub 403 阻断剔除：

    • 微软亚太 Anycast IP 中的 20.205.243.167 虽 Ping 延迟低，但被 GitHub 官方 WAF 封锁（返回 Access to this site has been restricted (403)）。脚本通过深度 HTTP 探测一票否决坏节点，稳定锁定 20.205.243.166。

  5. 语法规范：

    • 统一采用 |domain^$dnstype=A,dnsrewrite=NOERROR;A;ip 语法，避免传统 hosts 将 IPv6（AAAA）解析直接屏蔽导致部分双栈客户端超时。

4. AdGuard白名单使用

ADG的白名单叫做客户端id/Client ID, 没有配置客户端id的请求会被拒绝

通过申请一个泛域名证书*.doh.com此时你的dot/dns地址会变为客户端id.doh.com , doh地址为https://doh.com/123456/客户端id

5. 通过ECH加密可以突破SNI阻断

虽然dot也支持ECH但是安卓底层不支持, 目前ECH只能通过浏览器配置doh来使用
和之前的Cloudflare ECH代理原理类似

1. 突破原理

  • SNI 阻断机制：GFW 依靠在骨干网边界的 DPI 监听 TLS ClientHello。若读到黑名单明文 SNI，立即向双向注入 TCP RST 切断连接。

  • ECH (Encrypted Client Hello) 机制：
    客户端向支持的 DoH 服务器查询 Type 65 (HTTPS) 记录，获取服务器公钥。握手时将真正的域名加密封装在内层，外层明文 SNI 显示为中立的 cloudflare-ech.com，避开 GFW 明文匹配。

2. 客户端开启步骤

  • Chromium 内核 (Chrome / Edge / Brave)：

    1. 打开 chrome://flags，将 Encrypted ClientHello 设为 Enabled；

    2. 进入 设置 →→ 隐私和安全 →→ 安全 →→ 开启“使用安全 DNS”；

    3. 选择“自定义”，填入私有 DoH 地址：https://doh.com/123456/...；

    4. 彻底重启浏览器。

  • 验证 ECH 激活：
    访问 https://crypto.cloudflare.com/cdn-cgi/trace，若输出 sni=encrypted 即代表 ECH 已全链路生效。

3. 一些网站虽然托管在 Cloudflare使用了CDN但是没有开启ECH

这种情况可以通过将解析指向Cloudflare IPv4 + 合成 HTTPS/ECH 记录，过滤 AAAA

目前这种方案适用于pixiv/x/discord

为什么过滤 IPv6

  • Pixiv IPv6 返回 403 block_ip。

  • X IPv6 返回 403，正文仅为 IPv6。

  • Discord 为保持 A/HTTPS/ECH 一致性也统一返回空 AAAA。

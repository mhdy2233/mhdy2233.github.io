异次元发卡 3.5.6 插件开发与部署指南

适用版本：异次元发卡 3.5.6（提交 60b26c56f23d02da94715b1fc92899f02c86f35f）。

本文只描述仓库中实际存在的插件机制。Demo 只能说明目录和注解写法，不能作为“自制插件可以直接启用”的完整示例。

1. 先看结论

1.1 插件如何被检测

程序通过 Kernel\Util\Plugin::getPlugins() 扫描：

只要插件目录下存在可加载的 Config/Info.php，后台接口 /admin/api/plugin/getPlugins 就能读到插件元数据。检测插件不要求它出现在应用商店缓存中。

1.2 为什么原版不能正常使用自制插件

原版 kernel/Plugin/Hook.php 只在应用商店授权组件成功加载时读取：

TEXT1 行展开代码收起代码

这个文件由商店插件授权链生成并加密。自制插件虽然能被 getPlugins() 扫描到，但它的 #[Hook] 不会因此自动注册；后台启停也会走商店插件的 _plugin_start() / _plugin_stop()。

1.3 当前仓库的本地插件改动

本仓库增加了两个有限、独立的本地插件路径：

文件作用
kernel/Plugin/Hook.php继续加载商店 Hook；另外扫描不在 runtime/plugin/store.cache 中、且 STATUS=1 的本地插件，并注册其 #[Hook]。
app/Controller/Admin/Api/Plugin.php对不在商店缓存中的插件直接写入 Config/Config.php，执行启停状态 Hook，并记录管理日志。

商店插件仍使用原来的加密缓存和授权流程。仓库根目录的 kernel/Plugin.php 是应用商店授权组件，不应修改、解密或伪造；本文不依赖修改它。

2.1 命名规则

  • 目录名就是插件 ID，例如 OrderLog、TelegramNotification。

  • 目录名只能使用字母、数字和下划线，且必须以字母开头更稳妥。

  • 命名空间必须与目录名大小写一致：App\Plugin\OrderLog\...。

  • Hook 文件名必须与类名一致，例如 Hook/Main.php 对应 App\Plugin\OrderLog\Hook\Main。

  • Linux 区分大小写。不要照抄旧 CardAPI 示例中的大小写不一致写法。

  • 插件 ID 不要与 runtime/plugin/store.cache 中的商店插件重名；命中该缓存后会按商店插件处理，不会走本地路径。

4. Hook 机制

4.1 基本写法

php20 行展开代码收起代码

要求：

  1. Hook 方法必须是 public。

  2. #[Hook] 必须使用命名参数 point:，值来自 App\Consts\Hook。

  3. 方法参数顺序必须和挂载点实际传参一致；类型声明错误会让订单流程报错。

  4. Hook 方法应尽快返回。同步网络请求会增加付款请求耗时，失败应捕获异常，不能阻止支付和发货。

  5. 本地插件只有 STATUS=1 才注册；停用后下一次请求不会再调用它。

4.2 Hook 返回值

底层 Kernel\Util\Plugin::hook() 的行为：

  • string：追加到当前结果，适合输出 HTML/JS。

  • array：追加到结果数组，适合表格列、导航等结构化扩展。

  • Kernel\Plugin\Entity\Stock：立即返回库存对象。

  • null/无返回值：不改变结果。

页面挂载点常见做法是直接 echo，数据型挂载点则应按注释要求修改引用参数或返回数组。

8. 安装、启用和打包

8.1 手工安装

把插件目录放到：

TEXT1 行展开代码收起代码

然后：

  1. 检查 Config/Info.php、Config/Config.php 和命名空间。

  2. 确认目录名不是 store.cache 中已有插件 ID。

  3. 后台进入“通用插件”。

  4. 清空状态筛选，找到插件并打开配置。

  5. 保存配置后点击“启用”。不要只手工把 STATUS 改成 1，因为启用动作还负责注册 Hook。

8.3 1Panel / Linux 权限

PHP-FPM 用户必须能遍历插件目录并读写配置、日志。推荐：

Bash2 行展开代码收起代码

如果后台能看到插件但保存配置失败、日志为空，优先检查权限。Windows 生成的 ZIP 可能没有 Unix 目录模式，上传后目录会变成 644，PHP-FPM 无法进入 Config/、Hook/ 或 Support/。

8.4 修改代码后的缓存

本地 Hook 当前按请求扫描，通常刷新页面即可看到新代码；但 PHP OPcache 可能继续使用旧字节码。修改 Hook、控制器或模板后，按顺序处理：

  1. 后台停用再启用插件。

  2. 清理 PHP OPcache，或重启对应 PHP-FPM 容器。

  3. 浏览器强制刷新后台页面。

10. Telegram 订单通知插件

仓库中的 app/Plugin/TelegramNotification 是完整的付款成功通知实现，适合直接使用或作为网络通知插件参考。 位于 https://blog.mhdy.net/archives/yi-ci-yuan-fa-qia-de-zi-zhi-cha-jian

配置步骤

  1. 在 @BotFather 使用 /newbot 创建 Bot，保存 Token。

  2. 让 Bot 在目标私聊、群组或频道中收到一条消息。

  3. 调用 https://api.telegram.org/bot<TOKEN>/getUpdates 获取 message.chat.id。

  4. 论坛群需要额外填写 message_thread_id；普通群留空。

  5. 后台填写 Token、Chat ID，保存后点击启用。

重要配置

  • 默认只发送纯文本，不发送卡密。

  • commodity_mode=1 时只通知选中的商品。

  • notify_free=0 可忽略零元/赠送订单。

  • 联系方式默认脱敏；完整显示前确认隐私和群权限。

  • timeout 建议 3 秒以内；网络失败只记录日志，不阻塞支付和发货。

  • 自定义 API 只允许填写自己控制的 HTTPS 代理；Token 和订单内容会发送到该地址。

完整变量和故障排查见 app/Plugin/TelegramNotification/Wiki/README.md。

11. 自检与故障排查

11.1 插件不显示

依次检查：

TEXT4 行展开代码收起代码

查看后台接口 /admin/api/plugin/getPlugins 的响应，确认列表中有对应 id。

11.2 能显示但 Hook 不执行

  • Config/Config.php 的 STATUS 是否为 1。

  • 是否点击了后台“启用”，而不是只改文件。

  • Hook 类名、文件名、命名空间是否一致。

  • 方法是否 public，是否使用 #[Hook(point: ...)]。

  • 插件 ID 是否误出现在 runtime/plugin/store.cache。

  • PHP-FPM 用户是否能读取 Hook/ 目录。

  • 是否需要清理 OPcache。

可在测试环境运行已有检查脚本：

Bash1 行展开代码收起代码

该脚本会临时启用 Telegram 插件，确认 USER_API_ORDER_PAY_AFTER 已注册，然后恢复原配置。

11.3 配置或日志写入失败

检查：

Bash3 行展开代码收起代码

目录建议 755，文件建议 644；运行用户需要对配置文件和日志文件具有写权限。不要为了省事把整个站点改成 777。

11.4 订单流程被插件拖慢或报错

  • 网络请求设置短超时，并捕获 Throwable。

  • 不要在付款 Hook 中修改订单状态，除非插件明确负责发货且已处理幂等。

  • 不要把卡密放进外部通知。

  • 日志只记录订单号、结果和脱敏错误。

  • 先停用插件验证问题是否消失，再查看 runtime.log。

12. 发布前检查清单

  • 插件 ID 唯一，目录和命名空间大小写一致。

  • Config/Info.php 返回完整元数据。

  • Config/Config.php 至少有 STATUS。

  • 所有外部输入经过验证，后台接口有会话和 WAF 保护。

  • Hook 参数与触发点实际调用一致。

  • 网络调用有超时、异常处理和日志脱敏。

  • 不发送卡密、Token、密码和不必要的个人信息。

  • ZIP 根目录没有多余的插件名外层目录。

  • Linux 目录 755、文件 644，PHP-FPM 可读写必要文件。

  • 在测试订单上验证启用、停用、重复触发和网络失败场景。
